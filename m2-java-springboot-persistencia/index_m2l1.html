01Arquitecturas y capas

La lectura compara arquitectura monolítica, arquitectura en capas, MVC, microservicios y arquitectura n-capas. Sus figuras son diagramas, no ejemplos de código Java, así que se resumen aquí las responsabilidades que luego aparecen en los ejemplos.

Capa o componenteResponsabilidadTecnologías mencionadas
Presentación / vistaPresentar datos y captar entradas del usuario.Thymeleaf, JSP, JSF, HTML
ControladorRecibir solicitudes y coordinar la respuesta.Spring MVC, Spring Boot
ServicioAplicar reglas de negocio y coordinar operaciones.Spring Services
DominioRepresentar entidades y reglas del negocio.POJO, JPA
Repositorio / persistenciaAbstraer operaciones CRUD sobre los datos.Spring Data JPA, Hibernate
DatosAlmacenar y recuperar información.MySQL, PostgreSQL, Oracle

En una arquitectura en capas, la presentación delega al servicio, que usa repositorio para persistir. El flujo de regreso devuelve el resultado al usuario.

02Maven y Gradle

Ambas herramientas automatizan compilación, dependencias, pruebas y empaquetado. La lectura muestra cómo declarar una dependencia en cada una.

Maven: fragmento de pom.xml

<dependency>
  <groupId>org.springframework</groupId>
  <artifactId>spring-core</artifactId>
  <version>5.3.8</version>
</dependency>

Gradle: build.gradle (Groovy DSL)

dependencies {
    implementation 'org.springframework:spring-core:5.3.8'
}

Podria mencionarse Kotlin DSL, sin incluir un ejemplo de configuración Kotlin.

03JavaBean serializable

El ejemplo de la lectura declara Persona con constructor sin argumentos, propiedad privada y accesores. Aquí se reordena e indenta para poder leerlo; se incluye la clase completa.

import java.io.Serializable;

public class Persona implements Serializable {
    private static final long serialVersionUID = 1L;

    private String nombre;

    public Persona() {
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }
}

Se describe el constructor público sin argumentos como una convención de JavaBean y Serializable como parte de sus características. Los POJOs no están obligados a implementar esta interfaz.

04Enterprise JavaBeans

Un EJB se ejecuta en un contenedor Jakarta EE, que puede gestionar transacciones, seguridad, concurrencia y ciclo de vida.

Session bean sin estado citado

import jakarta.ejb.Stateless;

@Stateless
public class ServicioPersonaBean implements ServicioPersonaLocal {
    public Persona obtenerPersonaPorId(Long id) {
        // Implementación para obtener una persona por ID.
        return null;
    }

    public void crearPersona(Persona persona) {
        // Implementación para crear una nueva persona.
    }
}

Se utiliza el paquete antiguo javax.ejb.Stateless. Se muestra el paquete actual jakarta.ejb.Stateless; en un proyecto Java EE anterior a Jakarta EE 9, corresponde usar javax.ejb. Para compilar hacen falta la interfaz ServicioPersonaLocal, la clase Persona y una API/implementación EJB.

05Bean de Spring con @Component

Spring detecta esta clase durante el escaneo de componentes y administra su instancia como bean.

import org.springframework.stereotype.Component;

@Component
public class Persona {
    private String nombre;
    private int edad;

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    public int getEdad() {
        return edad;
    }

    public void setEdad(int edad) {
        this.edad = edad;
    }
}

Requiere Spring Context y una configuración que habilite el escaneo de componentes, por ejemplo Spring Boot.

06Configuración de Spring con @Bean

La anotación @Bean registra como bean el objeto que devuelve el método.

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ConfiguracionApp {
    @Bean
    public Persona persona() {
        Persona persona = new Persona();
        persona.setNombre("Carlos");
        persona.setEdad(40);
        return persona;
    }
}

Este ejemplo presupone la clase Persona de la sección anterior y las dependencias de Spring Context.

07Entidad JPA

Las entidades JPA representan datos persistidos. El ejemplo de la lectura se presenta con imports y constructores para mostrar una clase completa.

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class Persona {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nombre;
    private int edad;

    public Persona() {
    }

    public Long getId() {
        return id;
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    public int getEdad() {
        return edad;
    }

    public void setEdad(int edad) {
        this.edad = edad;
    }
}

El fragmento original usa anotaciones sin imports. Aquí se usan los paquetes jakarta.persistence; proyectos JPA anteriores a Jakarta EE 9 pueden usar javax.persistence. Una entidad JPA no necesita implementar Serializable por defecto.

08Vista JSP

El controlador prepara una lista de usuarios, la asigna a la solicitud y la reenvía a la vista JSP para generar la tabla.

Usuario.java

package com.comercioglobal.modelo;

    public class Usuario {
      private String nombre;
      private String correo;

      public Usuario(String nombre, String correo) {
        this.nombre = nombre;
        this.correo = correo;
      }

      public String getNombre() {
        return nombre;
      }

      public String getCorreo() {
        return correo;
      }
    }

UsuarioController.java

package com.comercioglobal.controlador;

    import com.comercioglobal.modelo.Usuario;
    import jakarta.servlet.ServletException;
    import jakarta.servlet.annotation.WebServlet;
    import jakarta.servlet.http.HttpServlet;
    import jakarta.servlet.http.HttpServletRequest;
    import jakarta.servlet.http.HttpServletResponse;
    import java.io.IOException;
    import java.util.Arrays;
    import java.util.List;

    @WebServlet("/usuarios")
    public class UsuarioController extends HttpServlet {
      @Override
      protected void doGet(
          HttpServletRequest request,
          HttpServletResponse response
      ) throws ServletException, IOException {
        List<Usuario> usuarios = Arrays.asList(
          new Usuario("Ana Pérez", "ana@example.com"),
          new Usuario("Luis Gómez", "luis@example.com")
        );

        request.setAttribute("usuarios", usuarios);
        request.getRequestDispatcher("/usuarios.jsp")
             .forward(request, response);
      }
    }

La vista es HTML5 generado por JSP. El controlador usa datos de muestra; en la aplicación real, se obtendrían desde un servicio o repositorio. 09Vista JSF

La lectura muestra una vista XHTML con una tabla enlazada a la propiedad usuarios de un bean administrado.

<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml"
      xmlns:h="http://xmlns.jcp.org/jsf/html"
      xmlns:f="http://xmlns.jcp.org/jsf/core">
<h:head>
    <title>Lista de Usuarios</title>
</h:head>
<h:body>
    <h1>Lista de Usuarios</h1>
    <h:dataTable value="#{usuarioBean.usuarios}" var="usuario">
        <h:column>
            <f:facet name="header">Nombre</f:facet>
            <h:outputText value="#{usuario.nombre}" />
        </h:column>
        <h:column>
            <f:facet name="header">Correo Electrónico</f:facet>
            <h:outputText value="#{usuario.correo}" />
        </h:column>
    </h:dataTable>
</h:body>
</html>

Requiere una aplicación Jakarta Faces y un bean usuarioBean con la propiedad usuarios.

10Servlet

La lectura advierte explícitamente que el ejemplo no está completo ni compila; sirve para mostrar el formato de una clase Servlet.

import jakarta.servlet.http.HttpServlet;

public class MyServlet extends HttpServlet {
    // Lógica del servlet no incluida en el material.
}

Para implementar una respuesta HTTP se deben sobrescribir métodos como doGet o doPost y configurar el mapeo. En Servlet anteriores a Jakarta EE 9, el import usa javax.servlet.http.HttpServlet.

11POJO

El código de la lectura presenta una clase Java sencilla, sin heredar de un framework. Se reconstruye el método getter que se había dividido entre dos fragmentos.

public class Persona {
    private String nombre;
    private int edad;

    public Persona(String nombre, int edad) {
        this.nombre = nombre;
        this.edad = edad;
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }

    public int getEdad() {
        return edad;
    }

    public void setEdad(int edad) {
        this.edad = edad;
    }
}

Ejemplo de clase ligada a un framework

import jakarta.servlet.http.HttpServlet;

public class MyServlet extends HttpServlet {
    // Esta clase depende de la API Servlet.
}

El ejemplo de Servlet no es un POJO independiente porque extiende una clase de la API Servlet. El POJO no está obligado a implementar Serializable ni a seguir el contrato JavaBean.

12Arquitectura de ejemplo

Se describe un flujo de creación de productos y pedidos con Spring Boot y MySQL, pero no incluye código Java concreto. El recorrido del caso queda resumido así:

  1. La vista Thymeleaf presenta el formulario del producto.
  2. El controlador Spring MVC recibe la solicitud.
  3. El servicio valida y aplica la lógica de negocio.
  4. El repositorio Spring Data JPA realiza la operación CRUD.
  5. La entidad de dominio se persiste en MySQL.
  6. El controlador devuelve o redirige a la vista con los datos actualizados.

No se inventa un proyecto ejecutable: faltarían la configuración de Spring Boot/MySQL, las entidades, repositorios, controladores y plantillas.
