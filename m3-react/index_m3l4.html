01Validación de propiedades

Las props transmiten datos del componente padre al hijo. El componente receptor debe tratarlas como entradas de solo lectura. La validación ayuda a detectar durante el desarrollo si los valores recibidos tienen los tipos esperados.

Con PropTypes se pueden declarar tipos y marcar propiedades obligatorias con isRequired. Una discrepancia genera una advertencia de desarrollo para facilitar el diagnóstico.

ValidadorTipo de valor esperado
PropTypes.stringTexto
PropTypes.numberNúmero
PropTypes.boolValor booleano
PropTypes.arrayArreglo
PropTypes.objectObjeto
PropTypes.funcFunción

Declarar tipos y valores predeterminados

import PropTypes from "prop-types";

function Producto({ nombre, precio, caracteristicas = [] }) {
  return (
    <article>
      <h2>{nombre}</h2>
      <p>Precio: ${precio}</p>
      <ul>
        {caracteristicas.map((item, indice) => (
          <li key={indice}>{item}</li>
        ))}
      </ul>
    </article>
  );
}

Producto.propTypes = {
  nombre: PropTypes.string.isRequired,
  precio: PropTypes.number.isRequired,
  caracteristicas: PropTypes.array
};

Un valor predeterminado apropiado, como un arreglo vacío, permite recorrer la propiedad sin que falle cuando no se proporciona. Los tipos declarados ayudan a detectar errores, pero no sustituyen la validación de datos necesaria en tiempo de ejecución.

02Referencias al DOM

Las refs permiten acceder a un nodo del DOM o a una instancia concreta cuando se necesita interactuar directamente con ella. Por ejemplo, pueden servir para enfocar un campo o leer su valor al enviar un formulario.

import { useRef } from "react";

function FormularioProducto({ onAgregar }) {
  const nombreRef = useRef(null);

  function enviar(evento) {
    evento.preventDefault();
    onAgregar(nombreRef.current.value);
  }

  return (
    <form onSubmit={enviar}>
      <input ref={nombreRef} aria-label="Nombre del producto" />
      <button type="submit">Agregar</button>
    </form>
  );
}

Usa refs para interacciones imperativas puntuales con el DOM. Para datos que controlan lo que se muestra, suele ser preferible el estado de React.

03Manejo del estado

El estado representa datos que pueden cambiar durante el uso de la aplicación y afectar la interfaz. Al actualizarlo con el setter de useState, React vuelve a renderizar los componentes que dependen de ese valor.

Lista de favoritos

import { useState } from "react";

function ListaDeFavoritos() {
  const [favoritos, setFavoritos] = useState([]);

  function agregarProducto(producto) {
    setFavoritos(actuales => [...actuales, producto]);
  }

  return (
    <section>
      <button onClick={() => agregarProducto("Bolsa reutilizable")}>
        Agregar a favoritos
      </button>
      <ul>
        {favoritos.map((producto, indice) => (
          <li key={`${producto}-${indice}`}>{producto}</li>
        ))}
      </ul>
    </section>
  );
}

El arreglo se actualiza creando uno nuevo, en lugar de modificar el existente. El setter funcional usa el valor más reciente del estado.

04Calificación con estrellas

Una calificación separa la presentación de una estrella individual de la lógica que mantiene el puntaje. El componente contenedor administra el estado y comunica la selección mediante una función.

import { useState } from "react";

function Estrella({ seleccionada, onSeleccionar }) {
  return (
    <button
      type="button"
      aria-label={seleccionada ? "Quitar estrella" : "Seleccionar estrella"}
      onClick={onSeleccionar}
    >
      {seleccionada ? "★" : "☆"}
    </button>
  );
}

function CalificacionEstrellas({ total = 5, inicial = 0 }) {
  const [calificacion, setCalificacion] = useState(inicial);

  return (
    <div aria-label={`Calificación: ${calificacion} de ${total}`}>
      {Array.from({ length: total }, (_, indice) => (
        <Estrella
          key={indice}
          seleccionada={indice < calificacion}
          onSeleccionar={() => setCalificacion(indice + 1)}
        />
      ))}
    </div>
  );
}

Al seleccionar una estrella, el evento actualiza el estado del componente contenedor y la interfaz refleja la nueva calificación.

05Estado dentro del árbol de componentes

Ubica el estado en el componente más cercano que lo necesite. Cuando varios componentes hermanos comparten los mismos datos, conviene elevar el estado a un ancestro común y pasar los datos y las funciones de actualización mediante props.

function App() {
  const [favoritos, setFavoritos] = useState([]);

  function agregarAFavoritos(producto) {
    setFavoritos(actuales => [...actuales, producto]);
  }

  return (
    <>
      <ListaDeProductos onAgregarFavorito={agregarAFavoritos} />
      <ListaDeFavoritos productos={favoritos} />
    </>
  );
}

Este enfoque mantiene una fuente de verdad para los datos compartidos: el padre conserva el estado, los hijos reciben los valores y notifican las acciones a través de callbacks.

06Integrar bibliotecas JavaScript

React puede combinarse con bibliotecas especializadas. D3, por ejemplo, permite construir visualizaciones basadas en datos, como una línea de tiempo de eventos donde la posición horizontal representa el tiempo transcurrido.

Al integrar una biblioteca que manipula el DOM, define con claridad qué parte administra React y cuál administra la biblioteca. Un elemento contenedor con una ref puede servir como punto de conexión; los efectos permiten sincronizar la integración con el ciclo de vida del componente.

import { useEffect, useRef } from "react";

function LineaDeTiempo({ eventos, dibujar }) {
  const contenedorRef = useRef(null);

  useEffect(() => {
    dibujar(contenedorRef.current, eventos);
  }, [dibujar, eventos]);

  return <div ref={contenedorRef} aria-label="Línea de tiempo" />;
}

Componentes de orden superior

Un componente de orden superior (HOC) es una función que recibe un componente y devuelve otro componente. Puede reutilizar comportamiento, envolver el componente original y entregarle datos o funciones adicionales mediante props.

function conProductos(Componente, obtenerProductos) {
  return function ComponenteConProductos(props) {
    const productos = obtenerProductos();
    return <Componente {...props} productos={productos} />;
  };
}

07Componentes funcionales y de clase

TipoCaracterísticas
FuncionalFunción que recibe props y devuelve JSX. Puede usar hooks para estado y efectos.
De claseExtiende React.Component, puede mantener estado y métodos de ciclo de vida, y define render().
 
function Saludo({ nombre }) {
  return <h2>Hola, {nombre}!</h2>;
}

class SaludoDeClase extends React.Component {
  render() {
    return <h2>Hola, {this.props.nombre}!</h2>;
  }
}

Los componentes funcionales son el enfoque habitual en React moderno. Los componentes de clase siguen siendo relevantes al leer o mantener código existente.

08Patrón Flux y flujo de datos

Flux organiza el flujo de datos en una sola dirección y ayuda a mantener claro dónde se actualiza el estado de una aplicación.

  1. Acción: describe un evento o una intención, como agregar un producto.
  2. Dispatcher: distribuye la acción a los manejadores correspondientes.
  3. Store: conserva los datos y la lógica de actualización.
  4. Vista: los componentes React muestran los datos y generan nuevas acciones ante interacciones.
// Acción que representa una interacción del usuario
const accion = {
  type: "producto/agregado",
  payload: { id: 1, nombre: "Bolsa reutilizable" }
};

En el ejemplo EcoMarket, una store mantiene los productos y notifica los cambios; un hook puede suscribirse a esa store, y la vista obtiene los productos para representarlos. La lectura también relaciona esta organización unidireccional con Redux.

09Repaso

  • Las props son entradas de solo lectura; valida los tipos esperados y proporciona valores predeterminados seguros cuando corresponda.
  • Las refs resuelven necesidades puntuales de acceso imperativo al DOM; el estado debe controlar los datos que afectan el renderizado.
  • Actualiza el estado de forma inmutable y eleva al padre los datos compartidos por varios componentes.
  • Integra bibliotecas externas delimitando la responsabilidad sobre el DOM y sincronizando su trabajo con los efectos de React.
  • Flux representa un flujo unidireccional de acciones a dispatcher, store y vista.

En síntesis: para compartir estado, el padre lo conserva y lo distribuye como props; Flux organiza ese flujo a escala de la aplicación.
